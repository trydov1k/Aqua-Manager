# Аналитика проекта: Aqua Manager


## 1. Общая информация

| Параметр | Значение |
|----------|----------|
| **Название** | Aqua Manager |
| **Жанр** | Экономический симулятор / Симулятор ухода за аквариумом |
| **Платформа** | Windows Forms (.NET) |
| **Язык разработки** | C# 10.0 / .NET 6.0 |
| **Архитектура** | Многослойная: Domain + Presentation |
| **Разработчик** | Дмитрий Максим (trydov1k) |

### 1.1. Краткое описание

Aqua Manager — это игра, в которой игрок выступает в роли владельца аквариумного бизнеса. Игра начинается с одного небольшого аквариума и стартовой рыбки. Основная задача — поддерживать здоровье питомцев, вовремя кормить их и следить за чистотой воды. Заработанные средства можно тратить на покупку новых видов рыб и расширение бизнеза — приобретение дополнительных аквариумов.

## 2. Архитектура решения

### 2.1. Структура проектов

Проект организован по принципу разделения ответственности:

```
AquaManager.sln
│
├── AquaManager.Domain (Class Library)
│   ├── Constants/           – статические конфигурационные данные
│   ├── Enums/              – перечисления (типы рыб)
│   ├── Factories/          – фабрики для создания объектов
│   ├── Interfaces/         – контракты для слабой связности
│   ├── Models/             – доменные модели (сущности)
│   ├── Services/           – бизнес-логика (GameEngine, IncomeService, SaveLoadService)
│   └── Properties/         – служебные ресурсы
│
└── AquaManager.Presentation (Windows Forms App)
    ├── Controls/           – пользовательские контролы (FishControl, ShopItemControl)
    ├── Extensions/         – методы-расширения для удобства
    ├── Forms/              – UI формы (MainForm, ShopForm, AquariumNameForm)
    ├── Models/             – вспомогательные модели для UI (SwimmingFish)
    ├── Resources/          – изображения рыбок и фонов
    ├── Properties/         – служебные ресурсы
    └── Program.cs          – точка входа в приложение
```

### 2.2. Архитектурные принципы

| Принцип | Реализация |
|---------|------------|
| **Разделение Domain и Presentation** | Domain не ссылается на Presentation, что позволяет изменять UI независимо от бизнес-логики |
| **Инкапсуляция** | Поля сущностей имеют приватные сеттеры, изменение состояния — только через публичные методы |
| **Событийно-ориентированная связь** | GameEngine оповещает UI через событие `StateChanged`, Presentation подписывается и обновляет отображение |
| **Внедрение зависимостей** | Сервисы получают ссылки на модели через конструкторы |
| **Принцип единственной ответственности** | Каждый класс решает строго одну задачу (GameEngine — игровая логика, IncomeService — доход, SaveLoadService — сохранение) |

## 3. Доменные модели (Domain Layer)

### 3.1. Fish (Рыбка)

| Поле | Тип | Описание | Доступ |
|------|-----|----------|--------|
| `Name` | `string` | Название рыбки (например, "Гуппи") | `get` |
| `Type` | `FishType` | Вид рыбки (enum) | `get` |
| `Hunger` | `double` | Уровень голода (0–100) | `private set` |
| `HungerRate` | `double` | Скорость падения голода (%/сек) | `get` |
| `Price` | `decimal` | Цена покупки | `private set` |
| `IncomeValue` | `decimal` | Доходность (монет за интервал) | `private set` |
| `IsAlive` | `bool` | Жива ли рыбка | `private set` |
| `Id` | `string` | Уникальный идентификатор | `get/set` |

**Методы:**
- `Feed()` — насыщает рыбку (устанавливает `Hunger = 100`)
- `UpdateHunger()` — уменьшает голод на `HungerRate`
- `Kill()` — убивает рыбку (обнуляет голод и цену)

### 3.2. Aquarium (Аквариум)

| Поле | Тип | Описание | Доступ |
|------|-----|----------|--------|
| `Name` | `string` | Название аквариума | `get` |
| `WaterCleanliness` | `double` | Чистота воды (0–100) | `private set` |
| `FishList` | `List<Fish>` | Коллекция рыбок | `get` |
| `Capacity` | `int` | Максимальное количество рыбок | `get` |

**Методы:**
- `CanAddFish()` — проверяет наличие места
- `AddFish(Fish fish)` — добавляет рыбку
- `RemoveFish(Fish fish)` — удаляет рыбку
- `CleanWater()` — устанавливает чистоту в 100
- `RemoveDeadFish()` — удаляет всех мёртвых рыбок
- `UpdateWaterCleanliness(double rate)` — уменьшает чистоту на указанную величину

### 3.3. Player (Игрок)

| Поле | Тип | Описание | Доступ |
|------|-----|----------|--------|
| `Money` | `decimal` | Количество монет | `get/set` |
| `Aquariums` | `List<Aquarium>` | Список аквариумов | `get/set` |
| `CurrentAquariumIndex` | `int` | Индекс текущего аквариума | `get/set` |

**Методы:**
- `AddMoney(decimal amount)` — увеличивает баланс
- `CanAfford(decimal amount)` — проверка достаточности средств
- `SpendMoney(decimal amount)` — списывает деньги
- `GetCurrentAquarium()` — возвращает активный аквариум

## 5. Сервисы бизнес-логики

### 5.1. GameEngine — ядро игры

Центральный класс, управляющий:
- Состоянием игрока и аквариумов
- Таймером игровых тиков (`_gameTimer`)
- Обработкой действий игрока (кормление, смена воды, покупки)
- Событием `StateChanged` для уведомления UI

**Основные методы:**

| Метод | Описание |
|-------|----------|
| `Start()` | Запускает игровые таймеры |
| `Stop()` | Останавливает таймеры |
| `NewGame()` | Создаёт нового игрока со стартовым аквариумом и рыбкой |
| `UpdateGameState()` | Логика обновления: уменьшение голода, загрязнение воды, смерть |
| `FeedAllFish()` | Кормит всех живых рыбок |
| `FeedSingleFish(string fishId)` | Кормит конкретную рыбку |
| `ChangeWater()` | Очищает воду в текущем аквариуме |
| `BuyFish(FishType type)` | Покупка рыбки |
| `BuyAquarium()` | Покупка аквариума |
| `RemoveDeadFish()` | Удаление мёртвых рыбок |
| `SwitchAquarium(int index)` | Переключение между аквариумами |

### 5.2. IncomeService — расчёт дохода

Сервис начисляет пассивный доход каждые 30 секунд. Доход рассчитывается как сумма `IncomeValue` всех живых рыбок во всех аквариумах игрока.

```csharp
private decimal CalculateTotalIncome()
{
    foreach (var aquarium in _player.Aquariums)
        foreach (var fish in aquarium.FishList)
            if (fish.IsAlive) total += fish.IncomeValue;
}
```

### 5.3. SaveLoadService — сохранение и загрузка

Сервис использует `System.Text.Json` для сериализации состояния `Player`. Особенности:
- Автоматическое создание резервной копии валидации загруженных данных
- Поддержка асинхронных операций
- Генерация отсутствующих идентификаторов при загрузке старых сохранений

Модель `SwimmingFish` хранит для каждой рыбки:
- Ссылку на доменную модель `Fish`
- Текущую позицию и скорость
- Уменьшенное изображение (масштабирование через `ScaleImage`)

- Позиция обновляется каждые 30 мс с добавлением скорости
- При касании границы компонента скорости меняют знак (отражение)
- Координаты корректируются `Math.Clamp` для предотвращения выхода за пределы

## 7. Игровые механики

### 7.1. Основной игровой цикл

```
1. Каждую секунду (_gameTimer)
   ├── Уменьшается голод всех живых рыбок (HungerRate)
   ├── Уменьшается чистота воды (WaterDirtRate)
   ├── Если чистота < DirtyWaterThreshold → голод уменьшается ещё раз (эффект ×2)
   └── Если голод ≤ 0 или чистота ≤ 0 → рыбка умирает

2. Каждые 30 секунд (_incomeTimer)
   ├── Суммируется IncomeValue всех живых рыбок
   └── Деньги игрока увеличиваются на полученную сумму
```

### 7.2. Экономическая система

**Доходы:**
- Пассивный доход от живых рыбок (каждые 30 секунд)

**Расходы:**
| Действие | Стоимость |
|----------|----------|
| Покормить всех | 5 × количество живых рыбок |
| Покормить одну рыбку | 5 |
| Сменить воду | 30 |
| Купить рыбку | 40–150 (в зависимости от вида) |
| Купить аквариум | 500 |

### 7.3. Кормление рыбок

Реализовано два способа:
- **Массовое кормление** — кнопка «Покормить всех»
- **Точечное кормление** — включение режима кормления и клик на рыбке в списке (`FishControl`)

### 7.4. Смертность рыбок

| Причина | Условие | Эффект |
|---------|---------|--------|
| Голод | `Hunger ≤ 0` | Рыбка умирает, её цена обнуляется |
| Грязная вода | `WaterCleanliness ≤ 0` | Все рыбки в аквариуме умирают |
| Ускоренное голодание | `WaterCleanliness < DirtyWaterThreshold` | Голод уменьшается в 2 раза быстрее |

## 9. Сценарии использования

### 9.1. UC-01: Пассивный доход

| Шаг | Действие | Система |
|-----|----------|---------|
| 1 | Игрок ждёт | Каждые 30 секунд IncomeService суммирует IncomeValue всех живых рыбок |
| 2 | — | Баланс игрока увеличивается, вызывается событие IncomeGenerated |
| 3 | — | GameEngine реагирует на событие и вызывает RaiseStateChanged |
| 4 | — | MainForm обновляет UI (отображение монет) |

### 9.2. UC-02: Смерть рыбок от голода

| Шаг | Действие | Система |
|-----|----------|---------|
| 1 | Игрок забыл покормить | Каждый игровой тик уменьшает Hunger |
| 2 | — | Когда Hunger ≤ 0, у рыбки вызывается Kill() |
| 3 | — | RaiseStateChanged уведомляет UI |
| 4 | — | MainForm обновляет список: мёртвая рыбка отображается серым цветом |

### 9.3. UC-03: Покупка аквариума

| Шаг | Действие | Система |
|-----|----------|---------|
| 1 | Игрок открывает ShopForm | Показ всех товаров |
| 2 | Игрок нажимает «Купить аквариум» | Вызывается BuyAquarium() |
| 3 | — | Открывается AquariumNameForm для ввода названия |
| 4 | — | Если название не введено, покупка отменяется |
| 5 | Игрок вводит название | GameEngine создаёт новый Aquarium |
| 6 | — | RaiseStateChanged, RefreshUI добавляет аквариум в ComboBox |

- Интуитивно понятный интерфейс с элементами управления реального времени

Кодовая база демонстрирует применение принципов **SOLID**, событийно-ориентированного программирования и разделения ответственности, что делает проект легко расширяемым и поддерживаемым для будущих улучшений (декорации, размножение, достижения, звуковое сопровождение и т.д.).
